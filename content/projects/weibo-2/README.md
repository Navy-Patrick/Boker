# 知微：微博舆情监控工作台

知微是一套面向非技术用户的本机微博舆情监控工具。用户可以在网页工作台中创建任务、维护多个关键词、启动帖子或“帖子 + 评论”采集、查看风险事件、生成 AI 研判报告，并按任务导入导出 Excel 数据。

首次启动、采集器配对或微博登录遇到问题时，请查看 [常见问题解答](./常见问题解答.md)。

项目采用“本机可见浏览器采集 + 本地采集器 + 数据面板 + 离线分析任务”的结构。微博账号由账号本人在专用 Chrome 中登录，登录 Cookie 不上传到业务数据库。

## 可以实现的目标

- 按监控任务管理一个或多个关键词。
- 为每个关键词保存独立增量游标、页码和上次成功时间。
- 手动采集或按任务周期调度采集。
- 选择只采帖子，或先采帖子再补采高价值评论。
- 对帖子和评论执行幂等去重，重复内容更新互动数据。
- 按任务查看内容、评论、采集历史、趋势、词云和风险事件。
- 对帖子和评论进行基础情感、风险评分，并按任务阈值生成事件。
- 使用 DeepSeek 或其他 OpenAI-compatible HTTPS 接口生成任务级 AI 研判。
- 按任务导出 Excel，并将知微导出的 Excel 回传更新帖子和评论。
- 断网时先写入本机持久队列，恢复后续传，不重复访问微博。

## 系统组成

```text
知微/
├── app/                 # Web 工作台、API、D1/SQLite 数据逻辑
├── collector/           # Node.js 本机采集器、Chrome CDP、持久队列
├── weibo_crawler/       # Python 离线分析与队列工作器
├── desktop/             # macOS 一键启动、停止和进度终端
├── docs/                # 产品、部署和运维文档
├── 启动知微.command
├── 停止知微.command
└── README.md
```

## 环境要求

- macOS。
- Google Chrome。
- Node.js 22 或更高版本。
- Python 3.11 或更高版本。
- 由账号本人正常登录、可访问的微博账号。

当前桌面启动脚本主要针对 macOS。Windows 和 Linux 尚未提供同等的一键安装体验。

## 快速开始

1. 双击 `启动知微.command`。
2. 首次运行会自动检查 Node.js、Python 和界面组件；缺失时下载到 `~/.zhiwei/runtime`，通常等待 5～20 分钟。
3. 等待首次加载页自动进入 `http://localhost:3000`。终端会持续显示当前下载或启动步骤。
4. 进入“系统设置”。
5. 点击“一键发现并配对本机采集器”。
6. 点击“打开/恢复微博登录”，在知微专用 Chrome 中完成登录。
7. 返回工作台，点击“验证登录状态”。
8. 创建或编辑监控任务，设置名称、关键词、频率、风险阈值、页数和评论数。
9. 在“监控任务”中选择“采帖子”或“帖子+评论”。

需要停止全部后台服务时，请双击 `停止知微.command`。仅关闭网页不会自动停止后台调度任务。

## 登录与采集器令牌

### 微博登录

知微使用独立 Chrome 用户目录：

```text
~/.zhiwei/weibo-chrome-profile
```

因此登录状态可以跨应用重启复用，并且不会与日常 Chrome 配置混用。

“打开/恢复微博登录”会根据当前状态工作：

- 未登录：打开微博登录页。
- 已登录：询问是否退出当前账号并重新登录。
- 确认退出：清除知微专用 Chrome 的微博 Cookie 和站点数据，再打开登录页。

### 采集器令牌

每台电脑首次启动时都会在本机生成独立令牌：

```text
~/.zhiwei/collector-token
```

点击“一键发现并配对本机采集器”后，面板会从 `127.0.0.1` 自动读取令牌并保存到当前浏览器，数据库只保存令牌哈希。普通用户不需要手动填写。密码框不回显明文属于正常安全设计。

部署到另一台电脑时会生成该电脑自己的令牌，不能复制旧电脑令牌或浏览器状态代替重新配对。完成一次自动配对后即可持续复用。

## 采集逻辑

### 帖子模式

- 按关键词搜索微博公开页面。
- 按时间窗口和增量页码继续采集。
- 过滤正文中不包含目标关键词的超话卡片或无关结果。
- 记录正文、公开链接、发布时间和互动快照。
- 内容 ID 已存在时更新互动数据，不重复插入。

### 帖子 + 评论模式

- 完成帖子采集后，优先选择高互动或高风险帖子。
- 每个采集分段最多补采 10 个帖子。
- 每帖评论数由任务配置决定，最大 20 条。
- 评论按点赞数排序并保留部分高赞评论。
- 已缓存的评论在缓存有效期内不会重复请求微博。
- 评论入库后执行情感、风险评分和事件对账。

评论采集依赖微博当前接口、帖子是否开放评论、账号权限和页面结构。因此某些帖子可能返回 0 条评论，这不等同于帖子采集失败。

## 数据存储与一致性

- 面板业务数据保存在本机数据库中。
- 采集器断网队列、评论缓存和令牌位于 `~/.zhiwei/`。
- 微博 Cookie 仅位于知微专用 Chrome 用户目录。
- 帖子、评论、采集批次和事件均使用幂等逻辑。
- 停止任务时会取消采集器队列；即使末尾批次抵达，入库 API 仍会拒绝暂停任务的数据。
- 风险事件在面板加载时按照任务阈值与帖子、评论风险分进行对账，补齐历史遗漏但不重新打开已关闭事件。

更换电脑后若只安装程序，不会自动获得旧电脑历史数据。需要迁移数据库和 `~/.zhiwei` 中必要状态，或使用按任务 Excel 导出保存业务数据。微博登录建议在新电脑重新完成，不建议复制 Cookie。

## 工作台功能

### 总览

- 总量、作者数、负面率和互动量。
- 舆情趋势和时间范围切换。
- 按任务生成词云。
- 查看高风险内容并跳转内容中心。

### 监控任务

- 新建、编辑、暂停、恢复、删除和合并任务。
- 多关键词独立增量状态。
- 选择帖子或帖子 + 评论模式。
- 分页查看历史采集批次和帖子、评论统计。

### 内容中心

- 按任务隔离展示帖子和评论。
- 按风险或情感筛选。
- 帖子和评论分别分页。
- 使用已登录的专用 Chrome 核验微博原文。
- 按任务下载或上传 Excel。

### 风险事件

- 按任务分类。
- 每 10 秒刷新面板数据。
- 同时支持帖子事件和评论事件。
- 提供“核验原文”和“关闭事件”。

### AI 分析

- 默认适配 DeepSeek OpenAI-compatible API。
- 按任务全量分批分析帖子和评论。
- API Key 仅保存在当前浏览器，不写入业务数据库。
- AI 输出仅作为辅助判断，必须结合原文人工核验。

## Excel 导入导出

每个任务可导出一个 `.xlsx` 文件，包含：

- 任务信息。
- 帖子。
- 评论。
- 风险事件。
- 采集历史。

上传时仅接受知微导出、任务 ID 一致、格式版本正确且不超过 12 MB 的文件。帖子和评论按来源 ID 更新，不重复创建。风险事件和采集历史用于回溯展示，不会通过 Excel 伪造采集记录。

## 安全、合规与使用边界

- 仅采集账号正常可见的公开内容。
- 不提供验证码破解、设备指纹伪造或访问控制绕过。
- 遇到 403、429、验证码或安全验证时应停止并由账号本人处理。
- 不应采集私信、非公开账号内容或规避权限的数据。
- 对外提供产品前，应取得必要授权，制定隐私政策、数据保留期限、删除机制和访问审计制度。
- 微博页面结构和平台规则可能变化，正式商用前应再次进行法律、平台条款和安全评审。

## 当前限制

- 微博页面或评论接口变化时，解析器可能需要更新。
- 账号权限、地区、安全验证和频控会影响采集数量。
- 评论模式只补采部分优先帖子和高赞评论，不是完整评论归档工具。
- 当前数据库和采集器主要面向单机或小团队使用。
- 当前没有完整的账号权限分级、企业单点登录和多租户隔离。
- 风险评分为规则与 AI 辅助结果，可能存在误报和漏报。
- Excel 回传主要恢复帖子和评论，不恢复伪造的运行历史。
- 关闭网页不会停止后台服务，应使用停止脚本或暂停任务。

## 运维位置

```text
~/.zhiwei/logs/                 # 服务日志
~/.zhiwei/outbox/               # 待续传批次
~/.zhiwei/collector-cache.json  # 评论与核验缓存
~/.zhiwei/collector-token       # 本机采集器令牌
~/.zhiwei/weibo-chrome-profile/ # 微博专用 Chrome 登录状态
```

出现问题时，先在系统设置执行“一键发现并配对”，再验证微博登录状态，最后检查 `~/.zhiwei/logs/`。
